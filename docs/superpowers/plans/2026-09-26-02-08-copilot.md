# Datum Copilot (Plans 02–08) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> The user asked for Plans 02–08 to be delivered in one run, so this file merges the seven plans. Each task still lists its interface and tests. The code lives in the commits, one commit per task.

**Goal:** Build everything from Foundation up to a complete BI copilot: pipeline, 5-layer guardrails, LLM router with failover and rule-based fallback, judge and risk gate, HITL, eval harness, Ops/Admin.

**Architecture:** Deterministic pipeline (`app/pipeline`). Each step is `async run(ctx)`. The orchestrator emits SSE events and writes to `pipeline_steps`. LLM calls always go through `LLMRouter`, which handles failover, the circuit breaker, chaos and the time budget. Providers are called over raw httpx (no SDK), so tests can use `httpx.MockTransport`. Embedding order: OpenAI (1024d) → Ollama `bge-m3` → local lexical hashing embedder (1024d, feature hashing over unaccented tokens), so linking/few-shot still work without an API key.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, psycopg 3 async (warehouse), sqlglot, pgvector, redis.asyncio, arq, PyYAML; React 19, TanStack Router/Query, Recharts, Monaco (`@monaco-editor/react`, bundled locally).

**Spec:** `docs/superpowers/specs/2026-09-26-text2sql-design.md`

**Status (2026-09-26):** Tasks 1–16 implemented on `feat/02-08-copilot`. 358 backend tests, 34 frontend tests, 3 Playwright E2E flows (failover flow auto-skips with fewer than two configured providers). Eval baseline = rule-based floor until cassettes are recorded with real API keys.

## Global Constraints

- Embedding dimension is fixed at 1024. Warehouse roles are `wh_viewer`/`wh_analyst` (read-only, `statement_timeout=10s`).
- `LIMIT ≤ 1000`. Router total budget 20 s. Retry at most 2× (429/5xx/timeout only), exponential backoff + jitter.
- Circuit: 5 failures/60 s → open 30 s → half_open lets 1 request through.
- Confidence = `0.2·self + 0.5·judge + 0.3·agreement` (no agreement → renormalize). Review threshold `confidence < 0.7`; fallback confidence < 0.8 → review.
- Judge rubric: `intent, schema_selection, joins_filters, aggregation, result_sanity` (1–5).
- Default chain: anthropic `claude-sonnet-5` → openai → gemini → ollama → rule_based. Only providers with a key/URL join the chain.
- Relative dates are anchored to `DATA_AS_OF` (default `2026-08-31`, the last day of seed data), not the wall clock, so answers and eval are deterministic.
- mypy `--strict`, ruff, eslint, `tsc --noEmit` must stay clean.

## Review Focus

1. LLM returns SQL with a trailing `;` or wrapped in a markdown fence → strip it before validating; must not be rejected as MULTI_STATEMENT. (Test in Task 3.)
2. Viewer asks about customer emails → SQL uses `v_customers_masked`, email is masked, run goes to NEEDS_REVIEW with reason `PII_ACCESS`. (Tests in Tasks 3, 9.)
3. No API key at all → system still answers common questions via rule-based, badge "Chế độ dự phòng"; unmatched question → clear message + suggestions, no made-up SQL. (Tests in Tasks 6, 9.)
4. SQL that returns 0 rows or NULL → result card shows "Không có dữ liệu", no crash while building chart_spec/summary. (Test in Task 8.)
5. Approving a review item for a question from a *viewer* must re-execute with the viewer role (not the analyst's) and re-validate L3 against the viewer allowlist. (Test in Task 11.)

- `app/pipeline/sql_guard.py`: `validate_sql(sql, role, layer) -> SqlCheck{ok, code, message, sql, tables, pii_columns}`.
- Tests: ≥60 attack cases (DML in CTE, `;`, comments, `pg_sleep`, catalog, `SELECT INTO`, `COPY`, dblink, unlisted columns, raw tables for viewer, UNION into a forbidden table, subquery in WHERE…) + valid cases (fence/`;` stripped, LIMIT added/clamped).
